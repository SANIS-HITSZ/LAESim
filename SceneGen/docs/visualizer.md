# Wireless City Factory 中文使用说明

> 本文保留原交付界面与参数说明。LAESim 集成后的安装、脚本路径和模块边界以 [SceneGen README](../README.md) 及 [RadioMapNav README](../../Examples/RadioMapNav/README.md) 为准；不再从原独立目录安装或构建验收包。

## 1. 软件是什么

Wireless City Factory 可视化器是一套本地运行的程序化城市与基站配置工具。它把工程中已有的城市生成、基站部署、场景验证和结果导出功能包装成了可视化界面。

使用者不需要编写配置文件，就可以在页面中选择城市和基站预设、修改参数、生成三维城市、检查建筑及基站信息，并导出后续仿真需要的标准文件。

本程序当前完成以下流程：

```text
配置城市和基站
        -> 生成并验证城市几何
        -> 部署基站和扇区
        -> 定义任务点、飞行高度和通信硬约束
        -> 三维交互显示
        -> （可选）Sionna RT 离线射线追踪
        -> 运行前一致性与可达性检查
        -> （可选）虚拟无人机位置查询
        -> 导出配置、场景、基站清单和 OBJ 模型
```

本程序既可以独立完成城市、基站和无线地图的可视化，也可以把当前结果一键导入并打开 LAESim/Unreal Engine。页面中的无人机在未启用“同步 LAESim”时只是位置和轨迹展示对象，不包含 AirSim 飞行动力学、碰撞或相机；启用同步后，页面会读取 LAESim/AirSim 的真实位姿。Sionna RT 无线计算是真实调用工程已有的离线射线追踪后端，不是前端伪造数据。

## 2. 能实现什么功能

### 2.1 城市生成

- 提供密集高层网格、不规则中层城区、紧凑放射低层和稀疏低层郊区四种城市预设。
- 支持修改城市尺寸、道路形态、道路间距和道路宽度。
- 支持修改建筑占地覆盖率、密度、高度分布、尺寸范围和建筑间距。
- 支持设置随机种子，使同一组参数能够重复生成相同结果。
- 自动执行边界、建筑冲突、建筑与所有道路避让、自由空间连通性和任务点有效性等验证；斜路、T 字路、放射路和环路都参与建筑占地检查。
- 当前版本使用平坦地面，不生成山地、坡地、桥梁或地形高程；地形作为后续独立功能处理。

### 2.2 基站配置

- 提供低频广域通信、Sub-6 GHz 低空宏站、4.9 GHz 通感实验和毫米波通感实验四类低空预设，并保留 UMa、UMi 传播校准参考和旧项目中间档。
- 支持道路网格、规则屋顶和随机屋顶等位置策略。
- 支持修改站点密度、最小站间距、天线高度和随机偏移。
- 支持修改载波频率、信道带宽、每扇区发射功率、下倾角、扇区数量和扇区方位角。
- 支持选择天线模型。
- 每个预设展示预设编号、版本、功能类型、证据等级、参数性质、适用场景和来源。
- 修改预设中的任意参数后，界面会自动标记为“自定义”，同时保留来源预设和修改字段列表。

这些预设不是厂家认证产品参数。`source_evidence_level` 表示来源等级，`parameter_status` 表示数值性质；当前四类低空预设的完整数值均按 `simulation_proxy` 管理。UMa 和 UMi 只用于传播模型校准，不表示所有实际运营商部署都必须使用完全相同的数值。详见 `docs/base_station_presets.md`。

### 2.3 三维查看与导出

- 支持旋转、缩放和平移三维城市。
- 支持透视视角和俯视视角切换。
- 支持单独显示或隐藏建筑、道路、基站、扇区和任务点。
- 支持点击建筑、基站、任务起点和终点查看详细信息。
- 支持下载 `config.json`、`scene.json`、`base_station_manifest.json` 和 `scene.obj`。

### 2.4 可选无线地图与虚拟无人机

- “启用 Sionna RT”默认关闭；开启后，生成城市时同时计算离线无线地图。
- 提供快速、平衡和精细三个计算质量档位。快速档的 40 m 网格只用于观察趋势；网格越细、射线样本越多，耗时和显存需求越高。
- 支持在最强宽带 RSS 与全频复用 SINR 热力图之间切换。这里的 RSS 是配置带宽内的总接收功率，不是 3GPP RSRP；SINR 假定所有扇区同频、同时满负载发射。
- Sionna RT 的射线传播始终使用界面中设置的真实载频。若载频超出某种 ITU-R P.2040 材料参数的有效范围，程序只把该材料的介电常数和电导率取值钳到最近有效边界，并在热力图图例显示“材料边界代理”；例如 700 MHz 的混凝土和干燥地面按 1 GHz 材料值计算，26 GHz 的干燥地面按 10 GHz 材料值计算。这是透明记录的工程近似，不等同于该频段已有完整材料标定。
- 色标默认按可检测网格的 P5-P95 自适应，便于看清空间差异；也可切换为固定色标以比较不同运行。完整信道网格始终着色：低于 `-125 dBm` 检测门限的有限数值使用色标最低档，灰色才表示真实数值缺失。图例分别报告“高于检测门限”和“网格有数值”的比例。
- “显示虚拟无人机”可单独开启或关闭，并可拖动轨迹位置或播放起点到终点的轨迹。
- 无线地图就绪后，无人机移动会查询当前位置的最强宽带 RSS、全频复用 SINR、服务小区和连接状态。
- “无线”“轨迹”“无人机”仍可通过视图顶部图层开关单独隐藏。

## 3. 启动方法

### 3.1 双击启动

双击工程中的：

```text
scripts\StartVisualizer.bat
```

程序会启动本地服务并自动打开浏览器。

### 3.2 PowerShell 启动

在工程根目录打开 PowerShell，执行：

```powershell
$env:PYTHONPATH = "$PWD\src"
& ".\.venv-sionna310\Scripts\python.exe" -m wireless_city_factory.web_app
```

默认访问地址为 `http://127.0.0.1:8765/`。如果 `8765` 端口已经被占用，程序会尝试后续端口，并在终端中显示实际地址。

关闭启动程序的终端窗口，或在该窗口中按 `Ctrl+C`，即可停止可视化器。

### 3.3 在另一台电脑首次安装

验收压缩包不包含作者电脑上的虚拟环境、运行缓存、生成结果和外部 LAESim checkout。接收者解压后，应在工程根目录打开 PowerShell，并先安装基础可视化环境：

```powershell
py -3.10 -m venv .venv
& ".\.venv\Scripts\python.exe" -m pip install --upgrade pip
& ".\.venv\Scripts\python.exe" -m pip install -e ".[dev]"
& ".\.venv\Scripts\python.exe" -m pytest
```

测试通过后，双击 `scripts\StartVisualizer.bat` 即可使用城市、基站、三维交互、任务配置与标准文件导出。输出默认保存在：

```text
%LOCALAPPDATA%\WirelessCityFactory\outputs
```

如需 Sionna RT，再另外建立 Python 3.10 环境并安装兼容的 NVIDIA 驱动、Sionna RT 2.x 与 Mitsuba CUDA 变体。最简安装命令如下，但 GPU/OptiX 是否可用仍须以启动页运行环境检查为准：

```powershell
py -3.10 -m venv .venv-sionna310
& ".\.venv-sionna310\Scripts\python.exe" -m pip install --upgrade pip
& ".\.venv-sionna310\Scripts\python.exe" -m pip install -e ".[dev,rt]"
```

如需 LAESim/UE 闭环，还必须由接收者自行准备 LAESim V1.5、Unreal Engine 4.27、Visual Studio C++ 工具链和已经构建的 AirSim 插件。随后执行：

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\scripts\SetupAirSim.ps1 -AirSimRoot "请替换为 LAESim 根目录" -Force
```

`Set-ExecutionPolicy -Scope Process Bypass` 只对当前 PowerShell 窗口生效，不修改系统永久策略。网页的 LAESim 功能还要求设置正确的 UE 4.27 路径；若未自动识别，可在启动前设置 `WCF_UE4_ROOT`。未安装 Sionna RT 或 UE/LAESim 时，基础可视化功能仍可独立验收，对应的可选按钮会禁用并显示缺失原因。

## 4. 界面组成

页面分为三个主要区域：

1. 左侧参数区：配置城市、基站、无线计算和虚拟无人机。
2. 右侧三维视图区：查看生成结果并进行交互。
3. 顶部导出区：下载当前已经成功生成的结果文件。

左侧参数区包含五个并列标签：城市、基站、无线与无人机、任务、LAESim。“任务”标签集中设置起终点、定高飞行高度、通信约束预设和运行前检查；LAESim 标签集中管理 UE 场景导入、打开和实时任务同步。

左下角状态文字含义：

- `准备生成`：参数已经加载，尚未生成。
- `正在生成`：后端正在生成和验证场景。
- `正在运行 Sionna RT`：正在执行离线射线追踪，请不要关闭页面或启动终端。
- `已生成`：产生了一个新的结果目录。
- `已复用`：参数、随机种子和生成器契约版本与已有结果完全相同，因此复用了原结果。
- 红色错误文字：当前参数不合法或城市未通过验证，需要根据提示修改。

## 5. 推荐的完整操作流程

### 第一步：选择城市

在左侧选择“城市”标签，然后选择一个城市预设。首次演示建议使用“密集高层网格”。

选择预设后，程序会自动填写道路和建筑参数，并立即重新生成右侧的城市预览。这个自动刷新只运行城市与基站阶段，不会启动 Sionna RT。

### 第二步：设置随机种子

随机种子决定随机布局。在同一生成器契约版本内，相同参数配合相同种子会得到相同城市；修改种子后，会得到同一种城市形态下的另一套布局。生成算法升级时，契约版本也会升级，程序会生成新的运行编号，不会错误复用旧算法的缓存。

验收或论文实验中应记录使用的随机种子，以便复现实验。

### 第三步：选择基站

切换到“基站”标签，选择基站预设：

- `低频广域通信站`：700 MHz 工程代理，适合郊区航线、物流和应急遥测。
- `Sub-6 GHz 低空宏站`：3.5 GHz 工程代理，适合普通城区、公网低空增强和航线通信。
- `4.9 GHz 通感一体实验站`：有国内公开试点支持的实验类型，适合景区、重点设施、港口和低空治理研究。
- `毫米波通感实验站`：面向热点和重点区域的探索性配置，遮挡敏感、站点更密。
- `3GPP UMa/UMi 校准参考`：用于传播模型和场景校准，不作为低空产品标准。
- `项目中间档（兼容）`：保留旧实验的敏感性配置。
- `自定义`：由使用者自行设置全部参数。

建议按任务选型：密集高层优先 Sub-6 GHz，并可增加 4.9 GHz 或毫米波热点；普通城区优先 Sub-6 GHz；郊区长航线优先低频广域并用中频补充容量；景区、港口和重点设施可选择 4.9 GHz 通感实验站。这里是建模起点，不是自动满足覆盖指标的结论。

### 第四步：设置任务

切换到“任务”标签。任务点支持两种方式：

- `自动选择可复现任务点`：先生成确定性候选点；启用无线计算后，如果候选点不在同一无线可行连通分量，系统会在同一城市、基站和门限下自动寻找相距较远且 X/Y 均不同的可行点，重新生成最终运行。
- `地图点选或坐标输入`：直接输入坐标，或者点击“在地图选起点/终点”后在右侧地面选择。手动任务点不会被程序偷偷替换，不可行时会明确阻止任务。

飞行高度是定高规划使用的高度，也会成为本次 Sionna RT 测量高度。任务预设提供可靠控制、普通遥测、视频回传和尽力而为四组项目实验门限；它们不是 3GPP 业务标准。高级修改会标为自定义，程序不会为了生成一条路线而自动降低门限。首版要求连续覆盖，最大中断比例固定为 0。

### 第五步：生成城市

修改随机种子或城市细节参数后，点击左下角“生成三维城市”，等待状态显示“已生成”或“已复用”。

城市预设会在选中后立即刷新；手动修改的其他参数仍需点击“生成三维城市”才会应用。

如需无线结果，先打开“无线与无人机”标签并启用 `Sionna RT`，再点击“生成城市并计算无线”。开关一旦启用，无论点击生成时停留在哪个标签页，程序都会计算无线地图。首次演示建议先用“快速预览”；确认闭环后再根据显卡资源选择更高质量。关闭开关后，生成操作只执行城市和基站阶段。

### 第六步：查看结果

生成完成后，查看右侧顶部统计信息和三维场景，检查建筑数量、基站数量、扇区数量和实际覆盖率。

如果启用了无线计算，程序会自动执行运行前检查：核对运行数据、城市/基站/无线/UE 来源指纹、网格完整性、飞行高度和连续可行航迹。只有全部通过才显示“可以导入 LAESim”。随后可切换 RSS/SINR 热力图和自适应/固定色标；拖动“轨迹位置”或点击“播放轨迹”，右上角将显示虚拟无人机当前位置的无线观测。

### 第七步：导入并打开 LAESim（可选）

浏览器中的当前生成结果是城市、基站、无线地图和 UE 场景的唯一数据源。每次成功生成后，“LAESim 场景”区域会显示运行编号、导入包状态、UE 导入状态和场景指纹一致性。

1. 先关闭正在运行的 Unreal Editor，避免地图或资源被占用。
2. 点击“导入或更新 LAESim”。程序会调用 UE 4.27 的命令行编辑器，把当前运行目录中的城市 OBJ、基站和任务点导入 `WirelessCityFactory.uproject`，同时备份并更新 `Documents\AirSim\settings.json`。
3. 等待状态显示“当前运行是最近一次导入记录”。程序除校验本运行目录的导入结果外，还维护唯一的活动导入记录；导入新城市后，旧运行目录不能继续冒充当前 UE 资源。
4. 点击“打开 LAESim 场景”。Unreal Editor 会打开本次导入对应的地图。
5. 在 UE 中点击工具栏上的“播放”，启动 AirSim/LAESim。
6. 切换到网页的“LAESim”标签，确认“任务进程”为“未启动”，并点击“执行任务”。网页会自动打开“同步 LAESim”。UE 用于观察真实飞行和碰撞，网页用于观察全局路线、信道热力图和无线指标。

新生成的 AirSim 配置默认使用 LAESim 多旋翼原生的 `FlyWithMe` 视角。旧运行目录中的 `settings.json` 不会自动更新；升级程序后必须重新生成城市并再次点击“导入或更新 LAESim”。播放期间可在 UE 画面中按 `B` 切回 `FlyWithMe`、按 `/` 切换 `SpringArmChase`、按 `F` 切换第一视角，视角切换不改变任务和日志。

通信约束任务先连接 LAESim 并读取当前位置，再完成普通路线和通信约束路线的预规划。只有完整航迹通过建筑碰撞和无线约束后，无人机才会起飞。若当前城市、任务点、高度和 SINR 门限不存在连续可行航迹，任务会保持原位并在网页给出原因；这表示约束不可满足，不应伪造一条航迹继续飞行。

#### 执行当前任务

推荐直接在网页“LAESim”标签中操作：

1. 确认当前参数已经生成、Sionna RT 无线地图存在、运行前检查为“可以执行”，并且当前运行与最近一次 UE 导入一致。
2. 确认 Unreal Editor 已经打开本次导入的地图，并已点击工具栏“播放”。
3. 点击“执行任务”。网页会再次进行指纹与运行前检查，只允许启动一个与当前运行编号一致的任务进程，并自动打开“同步 LAESim”。
4. 任务执行期间，“任务进程”显示“运行中”，网页与 UE 分别显示无线全局视图和真实飞行画面。任务正常结束后状态变为“已完成”。
5. 如需提前结束，点击“停止任务”。程序会先请求无人机悬停，写入 `type=stopped` 日志，释放 AirSim 控制权；若进程在 5 秒内没有受控退出，才会强制终止。

“执行任务”只有在当前运行未被参数修改、无线地图完整、运行前检查通过且最近一次 UE 导入与当前运行一致时才可用。“停止任务”只在网页启动的任务仍在运行时可用。UE 尚未进入 Play 时，任务会因无法连接 AirSim RPC 而失败，网页不会替用户点击 UE 的播放按钮。

每次网页任务都会在工程根目录的 `runtime\missions` 中保存两份同名文件：

- `<运行编号>-<UTC时间>.jsonl`：结构化任务与逐点无线观测日志；
- `<运行编号>-<UTC时间>.log`：任务进程的控制台输出，便于排错。

PowerShell 方式只作为调试或参数覆盖的备用入口。先从 LAESim 页复制“当前结果”的完整运行编号，再执行：

```powershell
$ROOT = "C:\Users\lenovo\Desktop\hgs\wireless_city_factory\wireless_city_factory"
$RUN_ID = "interactive_city-请替换为页面显示的编号"
$RUN = "$env:LOCALAPPDATA\WirelessCityFactory\outputs\$RUN_ID"
$env:PYTHONPATH = "$ROOT\src"

& "$ROOT\.venv-airsim310\Scripts\python.exe" `
    "$ROOT\scripts\run_laesim_connectivity_mission.py" `
    --run-dir "$RUN" `
    --output "$ROOT\laesim_connectivity_mission.jsonl"
```

不要继续使用上一轮命令中保存的旧 `$RUN`。命令默认读取该运行目录中已经冻结的起点、终点、高度、最低 SINR、最低 RSS 和最大中断比例，不需要再次手工填写；命令行显式传入参数只应用于有意进行覆盖实验的情况。备用命令不会受网页“停止任务”按钮管理，调试时应由操作者在对应终端中结束。

正确启动顺序为：在网页完成运行前检查，导入当前运行，点击“打开 LAESim 场景”，在 UE 中点击“播放”，最后点击网页“执行任务”。任务成功时网页显示 100%，JSONL 日志最后一行的 `type` 为 `complete`。

UE 4.27 默认可能启用 `Use Less CPU when in Background`。这会导致切换到 PowerShell 后仿真显著变慢，看起来像重新点击 UE 窗口才开始飞行。进入 `Edit -> Editor Preferences`，搜索 `CPU`，取消勾选 `Use Less CPU when in Background`。点击 UE 窗口不是任务协议的一部分；UE 进入 Play 后，即使窗口失去焦点也应继续仿真。

如果程序提示没有找到 UE 4.27，请在启动可视化器之前设置：

```powershell
$env:WCF_UE4_ROOT = "D:\Program Files\Epic Games\UE_4.27"
```

导入操作可能持续数分钟。导入按钮不会在后台替用户关闭已经打开的 Unreal Editor；打开地图后也仍需用户在 UE 中手动点击“播放”。

### 第八步：导出结果

确认结果正确后，点击页面顶部的“配置”“场景”“基站”或“OBJ”按钮下载文件。

顶部按钮导出的是最近一次成功生成的结果。如果修改了左侧参数但没有重新生成，下载的仍然是上一次结果。

## 6. 城市参数说明

### 6.1 城市预设

城市预设提供一组能够直接使用的参数。切换预设会整体替换道路和建筑配置；修改具体参数后，城市预设会显示为“自定义”。

### 6.2 随机种子

控制建筑布局、基站候选位置和任务点等随机过程。它是保证实验可复现的重要参数。

### 6.3 道路形态

- `Manhattan 网格`：横纵规则道路，适合规则高层城区。
- `有机不规则街区`：先建立规则街道节点，再以固定随机种子对节点进行二维错位，最后连接相邻节点，得到确定可复现、彼此连通的曲折街网和大小不一的街区。它不是数学 Voronoi 图，也不是真实 OSM 路网；内部配置标识保留为 `voronoi`，只是为了兼容旧配置。
- `BSP / T字路`：通过空间递归分割形成街区，包含较多 T 字路口。
- `放射与环路`：以放射道路和环路构成城市骨架。

### 6.4 场景范围

- `X尺寸`、`Y尺寸`：城市平面范围，单位为米。
- `道路间距`：相邻主要道路之间的参考距离。
- `道路宽度`：道路宽度，必须小于道路间距。
- `放射道路数`、`环路数量`：主要对放射与环路形态起作用。

修改道路形态、城市尺寸、道路间距或宽度后，必须重新点击生成按钮。后端会重新构造街区，并依据新道路重新放置和筛选建筑，因此道路和建筑应同步变化。

当前版本只考虑平坦地面。地形不能只作为一个视觉图层叠加：加入高程后，道路坡度、建筑基底、基站离地高度、无人机高度、Sionna RT 网格与材料、UE 碰撞及坐标转换都需要共同调整。因此首版先保证平地城市、基站和无线闭环可复现，山地或坡地留到后续独立阶段。

### 6.5 建筑分布

- `占地覆盖率`：期望由建筑底面覆盖的城市面积比例。
- `密度`：每平方千米的目标建筑数量。
- `高度分布`：建筑高度使用均匀、正态或对数正态分布生成。
- `最低/最高高度`：限制建筑高度范围。
- `平均高度/高度标准差`：控制高度分布的中心和离散程度。
- `最小/最大宽度与进深`：限制单栋建筑底面的尺寸范围。
- `建筑间距`：建筑之间要求保留的最小距离。

覆盖率和密度都是生成目标。由于建筑还必须避开道路、边界和其他建筑，最终实际值可能与目标值略有差异。

## 7. 基站参数说明

### 7.1 部署参数

- `位置策略`：决定基站放置在道路网格还是建筑屋顶等候选位置。
- `站点密度`：每平方千米部署的物理基站站点数量。
- `最小站间距`：两个物理站点之间允许的最小距离。
- `天线高度`：天线的安装高度。
- `高度语义`：区分绝对离地高度和屋顶以上杆高。
- `参考站间距`：用于说明该预设对应的典型站间距，不等于每对基站的距离都会严格相同。
- `随机偏移`：在规则候选点附近增加的位置扰动。

### 7.2 射频与扇区参数

- `功率`：每个逻辑扇区的标称发射功率，单位为 `dBm/sector`。
- `载波频率`：所有站点和扇区使用的中心频率，单位为 GHz；该值会直接传给 Sionna RT。
- `信道带宽`：接收噪声功率和无线配置使用的带宽，单位为 MHz；该值会直接传给 Sionna RT。
- `下倾角`：天线波束向地面倾斜的角度。
- `扇区数量`：每个物理基站包含的逻辑扇区数。
- `扇区方位角`：各扇区在水平面的朝向，数量必须与扇区数量一致。
- `天线模型`：后续无线仿真使用的天线阵列标识。

一个物理站点可以包含多个逻辑扇区。例如 30 个物理站点、每站 3 个扇区，对应 90 个逻辑扇区。

### 7.3 来源、可信度与自定义

- `preset_id` 和 `preset_version`：预设的稳定身份与版本。
- `source_evidence_level`：A 为政策、3GPP 或正式标准组织文件；B 为运营商或设备商公开案例；C 为论文、招投标或二手材料；D 为缺少公开来源的经验参数。
- `parameter_status`：`public_verified`、`trial_specific`、`simulation_proxy` 或 `unknown`。当前预设中的完整数值组合均是 `simulation_proxy`。
- `source_preset_id`：自定义配置从哪个预设开始修改。
- `modified_fields`：相对来源预设发生变化的字段。
- `sensing_enabled`：表示预设面向通感研究，不表示当前 Sionna RT 已经实现目标探测算法。

Sionna RT 当前计算传播路径、宽带接收功率和全频复用 SINR。探测距离、距离和角度分辨率、虚警率与漏检率不能从 RSS 热力图直接推出，必须另接感知模型或实测数据。

## 9. 怎么看生成结果

### 9.1 顶部统计值

- `建筑`：实际成功放置的建筑数量。
- `站点`：物理基站数量。
- `扇区`：所有物理站点包含的逻辑扇区总数。
- `覆盖率`：实际建筑底面积占城市总面积的比例。

例如 `30 站点，90 扇区` 表示场景中部署了 30 个物理基站，每个站点包含 3 个逻辑扇区。

### 9.2 判断结果是否正常

一次正常生成应满足：

1. 左下角显示“已生成”或“已复用”，没有红色错误信息。
2. 右侧能够看到建筑、道路和基站，而不是空白画布。
3. 建筑、站点和扇区统计值符合所选城市及基站类型的大致特征。
4. 绿色起点和红色终点位于有效自由空间中。
5. 点击建筑和基站能够显示对应属性。
6. 顶部四个导出按钮处于可用状态。

### 9.3 结果边界

黄色扇区箭头只表示基站扇区朝向，不能代表覆盖范围。只有在启用 Sionna RT 并成功生成无线地图后，彩色热力图和右上角无线观测才是射线追踪结果。网页无人机只提供坐标和轨迹演示，不代表真实飞行动力学；真实无人机运动仍需要 UE/LAESim/AirSim。

### 9.4 同步 LAESim 双画面

“同步 LAESim”关闭时，网页无人机按滑块或“播放轨迹”做独立演示。打开同步后，网页会轮询本机 LAESim 任务状态，并自动完成以下操作：

1. 加载 LAESim 正在使用的同一份城市、基站和 Sionna RT 离线信道地图；
2. 绘制通信约束规划器实际生成的轨迹；
3. 用 LAESim RPC 返回的真实位姿移动网页无人机；
4. 显示当前位置的 RSS、SINR、服务小区和连接状态；
5. 任务完成后显示 100% 和“LAESim 任务完成”；操作者点击停止后显示“已停止”。

同步期间，网页独立播放按钮、高度输入和轨迹滑块会被锁定，防止虚拟位置覆盖真实位置。UE 窗口用于观察真实飞行和碰撞，网页用于观察全局路线、信道热力图和无线指标，两者展示的是同一次任务。

网页使用俯瞰全局视角，UE 默认使用 `FlyWithMe` 跟随视角，因此两边的观察角度不会完全相同；城市几何、任务点、轨迹和无人机坐标仍由同一运行目录与场景指纹约束。若 UE 只显示天空或城市外部，可先启动任务让无人机转向城市内部，或在 UE 画面中切换相机；这不代表坐标或场景不一致。

同步会校验运行编号以及配置、场景、基站、无线地图和 UE 来源指纹。任一项不同，或网页参数修改后尚未重新生成时，网页会拒绝加载旧任务，避免把不同城市的 UE 位姿、路线和信道地图混合显示。

## 10. 导出文件说明

### 10.1 `config.json`

保存本次生成使用的完整输入配置，包括随机种子、城市尺寸、道路、建筑、基站、任务高度、无线参数标识和 UE 阶段开关。它用于记录和复现实验。

`ue.enabled` 始终为 `true`，因此每次浏览器生成都会产生与当前场景匹配的 `ue_bundle` 和 `ue_manifest.json`。`radio.enabled` 取决于页面中的 Sionna RT 开关，可用于复现本次是否执行了无线计算。

### 10.2 `scene.json`

城市的标准结构化场景文件，包含场景边界、坐标约定、建筑、道路、基站、任务点、统计信息和场景指纹。它是后续无线计算与 UE 导入共享的城市数据源。

### 10.3 `base_station_manifest.json`

基站和逻辑扇区清单，包含物理站点编号与位置、天线高度、部署类型、标称发射功率、扇区编号、方位角、下倾角、天线模型和场景指纹关联。新版还保存预设编号及版本、功能类型、证据等级、参数性质、感知能力、来源预设和修改字段，便于复现实验与审计参数来源。

后续 Sionna RT 和运行时无线查询使用这份清单识别发射端。

### 10.4 `scene.obj`

通用 Wavefront OBJ 三维网格，可供三维软件或后续导入流程读取。它主要描述城市几何，不代替包含完整语义信息的 `scene.json`。

## 11. 结果保存位置

所有运行结果默认保存在当前 Windows 用户的本地应用数据目录：

```text
%LOCALAPPDATA%\WirelessCityFactory\outputs\<运行编号>
```

通常对应：

```text
C:\Users\<用户名>\AppData\Local\WirelessCityFactory\outputs\<运行编号>
```

将结果放在用户数据目录，可以避免程序位于桌面、只读目录或压缩包解压目录时出现 `WinError 5` 写入失败。启动终端也会显示实际保存位置。

如需指定其他位置，可以在启动前设置环境变量 `WCF_VISUALIZER_OUTPUT`。

运行编号类似 `interactive_city-a52d9e4bbb87`。后半部分由配置内容和生成器契约版本共同计算得到。在同一契约版本内，同样的参数和随机种子会对应同一个运行编号，并复用已有结果。

生成算法发生会改变场景结果的升级时，开发者必须同时提升生成器契约版本。这样即使参数和随机种子不变，也会得到新的运行编号。旧结果会保留在磁盘上用于追溯，但不会再被新算法复用。

目录中还可能包含：

- `manifest.json`：整次流水线的状态摘要。
- `city_manifest.json`：城市生成阶段摘要。
- `preview.svg`：二维场景预览图。
- `radio_manifest.json`：Sionna RT 版本、计算参数、结果摘要和文件校验信息。
- `radio_volume.npz`：供热力图和位置查询使用的离线信道体数据。
- `ue_manifest.json`：UE 导入包的契约、目标资源名和源场景指纹。
- `ue_bundle\`：供 UE 4.27 导入的 OBJ、Python 导入脚本和 AirSim 配置。
- `ue_import_result.json`：UE 命令行导入成功后产生的结果标记，包含已导入地图路径和源场景指纹。

## 13. 常见问题

### 修改参数后地图没有变化

城市预设会自动刷新。随机种子、道路、建筑或基站的手动修改需要点击“生成三维城市”才会应用。

### 显示“已复用”是不是失败了

不是。它表示相同配置以前已经用当前生成器契约版本成功生成，程序直接读取已有结果，以避免重复计算。算法升级会改变契约版本并生成新的运行编号，不会复用旧算法缓存。

### 为什么目标建筑数量和实际数量不同

建筑需要同时满足道路避让、边界、最小间距和自由空间验证。目标密度过高时，生成器可能无法放入全部候选建筑。

### 为什么更换道路后建筑数量也会变化

道路不是只画在建筑上方的装饰层。生成器会用每条道路的实际宽度检查建筑底面；与直路、斜路、T 字支路、放射路或环路相交的候选建筑都会被丢弃并重新尝试，因此不同道路形态会得到不同的建筑布局和数量。

### 为什么扇区数比基站数多

“站点”表示物理基站，“扇区”表示该站点上的逻辑小区。三扇区基站会让扇区总数等于站点数的三倍。

### 为什么选择了预设，却显示“自定义”

选择预设后，只要修改其中任意基站参数，系统就会将其标记为自定义，避免把修改后的参数误认为标准预设。

### 为什么 Sionna RT 开关不可用

当前启动进程没有找到 Sionna RT 与 Mitsuba。关闭窗口后重新双击 `scripts\StartVisualizer.bat`；启动器会优先使用项目中的 `.venv-sionna310` 环境。

### 为什么无线计算比较慢

Sionna RT 需要对建筑和基站执行射线追踪。城市越大、基站扇区越多、网格越细、样本数和反射深度越高，耗时与显存需求越大。先用“快速预览”验证流程，再选择平衡或精细档。

### 为什么打开 Sionna RT 后仍没有热力图

切换到“无线与无人机”标签，打开 Sionna RT 后点击“生成城市并计算无线”，并等待状态显示“无线地图就绪”。无线数据就绪后，彩色热力图会自动显示；顶部“无线”图层开关可以隐藏或恢复它。

### 为什么提示“没有连续可行航迹”

通信约束规划使用硬门限：路线上的采样点必须同时满足建筑避碰、无线地图有效和最低 SINR 等要求。即使局部位置的 SINR 很高，只要起点与终点之间的有效网格被高楼、无覆盖区域或低 SINR 区域切断，规划器也必须拒绝执行。

处理顺序建议为：先确认任务高度与无线地图高度一致；再使用更细的无线网格；随后调整任务点或增加合理的基站密度；最后才根据实验定义重新评估 SINR 门限。降低门限并不一定有效，因为无覆盖网格和建筑碰撞不会随着门限降低而消失。

### 为什么 LAESim 按钮是灰色的

刚打开页面、生成尚未完成，或修改参数后尚未重新生成时，LAESim 按钮会被禁用。参数一旦改变，当前画面和待导入配置就可能不是同一场景，页面会标记“参数已修改，请重新生成”。重新生成后，“导入或更新 LAESim”会恢复可用。

“打开 LAESim 场景”只有在 UE 导入结果与当前场景指纹完全一致时才可用。如果显示“指纹不一致，需要重新导入”，先关闭 UE，再点击“导入或更新 LAESim”。

“执行任务”还要求 Sionna RT 无线地图存在、运行前检查通过，并且当前运行是最近一次 UE 导入；缺少任一条件时按钮保持灰色，旁边状态会说明原因。“停止任务”在没有由本网页启动的活动任务时保持灰色，这是正常保护状态。

### 指纹一致性有什么用

场景指纹由标准化场景数据计算得到。浏览器结果、Sionna RT 数据、UE 导入包和实时任务状态都记录对应指纹；最近一次 UE 导入还单独写入活动导入记录。只有运行编号及配置、场景、基站、无线和 UE 来源全部匹配，程序才允许同步，从而避免把 A 城市的无线地图、B 城市的 UE 画面和 C 城市的任务轨迹混在一起。该检查能证明文件和最近导入操作一致；用户仍应通过程序按钮打开地图，不要在 UE 中手工切换成其他地图。

### 没有运行 UE，为什么曾显示“任务场景不一致”

实时任务状态保存在 `runtime\laesim_live_state.json`。旧版本会无限期读取上次遗留文件；当前版本增加了 30 秒实时租约，超过 30 秒没有任务更新就显示“等待 LAESim 任务启动”，不会把昨天的状态误报为当前任务。刚完成或失败的任务信息会先显示，随后自动回到未连接状态；完整结果仍保存在任务 JSONL 日志中。

### 怎么判断任务日志是否正确

每行都是一个独立 JSON 对象：第一行 `type=mission` 保存规划路线和规划指标；中间的 `type=sample` 保存 UTC 时间、AirSim/场景位姿、速度、碰撞状态、当前动作、逐小区 RSS、服务小区、SINR 和 outage；最后一行 `type=complete` 保存最终位姿和终点误差。

一次成功任务至少应满足：最后一行是 `complete`；`final_error_m` 小于规划器到达容差；所有采样点 `has_collided=false`；需要连续连接的任务中所有采样点 `radio.outage=false`；最低 SINR/RSS 不低于本次任务门限。日志中的 outage 从当前版本起使用任务自己的 SINR 和 RSS 硬门限，而不是固定使用运行时默认值。

## 14. 验收建议

建议按下面的顺序向师兄展示：

1. 启动可视化器并说明它可以独立使用，也可以把同一场景接入 LAESim/UE。
2. 选择“密集高层网格”，将道路形态设为“BSP / T字路”，基站选择“Sub-6 GHz 低空宏站”，生成并展示三维城市。
3. 旋转、缩放、俯视并开关图层。
4. 点击一栋建筑和一个基站展示属性。
5. 展示物理站点数与逻辑扇区数的关系，例如 5 个三扇区站点对应 15 个扇区。
6. 修改一个基站参数，展示预设自动变为“自定义”。
7. 切换为“稀疏低层郊区 + UMa”并重新生成，比较两种场景。
8. 打开 Sionna RT，使用快速预览生成无线地图，切换宽带 RSS/全频复用 SINR 热力图和自适应/固定色标。
9. 拖动或播放虚拟无人机轨迹，展示当前位置的无线观测。
10. 关闭无线或无人机功能，证明两项功能可以独立控制。
11. 关闭 Unreal Editor，点击“导入或更新 LAESim”，展示指纹一致状态。
12. 点击“打开 LAESim 场景”，在 UE 中点击播放，说明 UE 与网页分别承担真实飞行画面和全局无线观测。
13. 回到网页点击“执行任务”，同时展示 UE 中的真实无人机运动和网页中的路线、热力图、当前位置无线指标；必要时演示“停止任务”的悬停和释放控制流程。
14. 下载标准文件并说明它们在复现和审计中的用途。

通过这套演示可以证明：城市参数可配置、城市形态具有差异、基站具有典型预设且允许自定义、三维地图可以交互、结果可以复现和导出。

## 15. 当前完成边界与后续事项

师兄提出的主闭环已经完成：可复现程序化城市、统一基站清单、Sionna RT 离线信道地图、同源 UE/LAESim 导入、真实 UAV 位姿驱动无线查询，以及通信硬约束下的轨迹示例均可运行和保存日志。工程仍遵守“不实现训练算法”的原始边界；通信感知规划是 use case 的确定性专家示例。

仍需明确以下限制：

- 网页“快速预览”采用 40 m 网格，只用于交互演示；工程另有 2 m、四高度的 `production_v1` 正式数据集，新的交互配置若要用于论文数值结论，仍需按正式预算重新计算。
- 在线阶段查询预计算的静态 Sionna RT 地图，不会在每个飞行时刻重新做射线追踪；动态车辆、行人、动态遮挡、天气和风场尚未建模。
- 当前无线接口位于 Python/AirSim 外部桥接层，不是 UE C++ 原生传感器插件。它已经满足当前位置查询和日志闭环，但若论文或后续平台要求蓝图内直接读取，需要再封装插件接口。
- 文件指纹可以证明网页、清单、无线数据和最近一次 UE 导入一致，但 AirSim RPC 当前不能回报 UE 编辑器实际加载地图的指纹。应始终使用网页“打开 LAESim 场景”，不要进入 UE 后手工切换地图。
- 网页已经提供“执行任务/停止任务”按钮，并以独立受控进程连接 AirSim；UE 仍必须由用户打开正确地图并手动进入 Play，网页不能替代 Unreal Editor 的运行状态。
- 当前只支持平地、静态建筑和定高飞行；地形、动态障碍、多高度在线规划及设备标定属于后续扩展。
- 业务门限和基站完整参数仍是透明的实验预设或仿真代理，不应表述为普适的 3GPP 产品强制值。

## 16. 验收包与交付范围

当前版本不再单独打包 WirelessCityFactory。请在 LAESim 根目录生成可移植源码：

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\PreparePortableSource.ps1 -DestinationRoot 'H:\LAESim-portable'
```

目标必须为空或不存在。此入口复制 LAESim 平台源码，并排除虚拟环境、生成地图、UE 构建产物和复制的插件。测试需另行运行根目录 `python -m pytest` 和核心验证入口。以下清单仅描述原始验收 ZIP，不是当前打包格式。

验收包包含：

- `src`、`configs`、`scripts`、`tests`、`docs`；
- `README.md`、`LICENSE`、`PROVENANCE.md`、`pyproject.toml`；
- 精简 UE 工程骨架，包括 `.uproject`、`Config`、`Source` 和导入脚本；
- 包内文件哈希清单 `PACKAGE_MANIFEST.sha256`。

验收包不包含：

- `.venv*`、Python 缓存、pytest/ruff 缓存和浏览器运行数据；
- `examples/outputs`、`runtime`、无线地图、任务日志和本机生成的城市；
- UE 的 `Binaries`、`Intermediate`、`Saved`、`DerivedDataCache`、`.vs` 和已导入地图；
- 外部 AirSim 插件、LAESim checkout、Unreal Engine、CUDA/Sionna 安装和本机用户配置。

这些排除项要么可以由源码重新生成，要么属于第三方软件或本机状态。接收者若要验收完整 LAESim 闭环，应按 3.3 节准备外部环境并重新导入当前生成的场景，不能把压缩包中的源码等同于已经安装好的 UE、LAESim 或 Sionna RT 运行环境。
